## 二、P0 验证用例

### TC-01：`resolveEvent` 推进 gameTime

**操作路径**：历练 → 触发事件 → 选择选项 → 结算

**前置条件**：能进入历练流程并触发随机事件

**测试步骤**：

1. 进入游戏，记录顶栏日期 `T0`（例：纪元1年1月1日）
2. 点击「⚔ 历练」→ 选择「吸纳」或其他遭遇
3. 等待历练演出完成（EventScreen）
4. 选择任意事件选项（任意选项均可）
5. 观察结算后主界面顶栏日期 `T1`
6. 对比 `T0` 和 `T1`，确认天数变化

**预期结果**：

- 事件选项有 `timeCost` 字段（默认1天）
- `T1 = T0 + timeCost` 天数
- 例：`T0 = 纪元1年1月1日` + `1天` → `T1 = 纪元1年1月2日`

**验收标准**：
- [ ] 结算后日期推进了正确天数
- [ ] 日志面板显示 `⏱ 消耗 N 天`（P2）

**参考代码位置**：`src/store/accountStore.ts` `resolveEvent`（约 line 468-509）

---

### TC-02：`tickIdle` 推进 gameTime

**操作路径**：挂机 tick

**前置条件**：游戏主界面可操作

**测试步骤**：

1. 进入游戏，记录顶栏日期 `T0`
2. 开启挂机模式（点击「挂机」按钮）
3. 等待至少 3 个 tick（每个 tick 约 3 秒，可观察）
4. 记录停止挂机后的日期 `T1`
5. 计算实际推进天数

**预期结果**：

- 每个 tick 推进 **1 天**
- `T1 = T0 + N 天`（N = tick 次数）
- 日志面板显示 `⏱ 挂机 1 天`（如有）

**验收标准**：
- [ ] 挂机 N 个 tick 后，日期推进了 N 天
- [ ] 挂机过程中日期实时更新

**参考代码位置**：`src/store/accountStore.ts` `tickIdle`（约 line 364）

## 五、边界条件测试

### TC-05：跨月时间推进

**条件**：推进后日期超过当月天数

**测试步骤**：

1. 记录日期 `T0 = 纪元1年1月30日`
2. 执行一次推进 **3 天** 的操作
3. 验证 `T1 = 纪元1年2月2日`（正确跨月）

**预期结果**：月份和年份正确递增

---

### TC-06：闰年判断

**条件**：游戏时间到达 2 月

**测试步骤**：

1. 记录日期 `T0 = 纪元1年2月27日`（实际年份 2016 = 闰年）
2. 执行一次推进 **2 天** 的操作
3. 验证 `T1 = 纪元1年2月29日`（闰年 2 月有 29 天）

**预期结果**：闰年 2 月有 29 天，正确进位

**参考**：
- 闰年：实际年份 % 4 == 0 且 % 100 != 0，或 % 400 == 0
- 纪元 1 年 = 实际年份 2016（闰年）
- 纪元 5 年 = 实际年份 2020（闰年）

---

### TC-07：跨年时间推进

**条件**：推进后年份递增

**测试步骤**：

1. 记录日期 `T0 = 纪元1年12月30日`
2. 执行一次推进 **3 天** 的操作
3. 验证 `T1 = 纪元2年1月2日`（正确跨年）
