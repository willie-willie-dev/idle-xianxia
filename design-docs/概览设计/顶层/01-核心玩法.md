## 二、核心循环

一句话：**从角色界面触发，进入连续事件选择，获得回馈。**

```
角色界面（触发）
    │
    ▼
进入事件选择
    │
    ▼
事件选项
    │
    ▼
结算结果 + 获得回馈
    │
    ▼
角色成长（属性/性格/资源等）
    │
    ▼
回到角色界面
```

这是一条**闭合的反馈循环**，玩家的成长驱动来自这条循环，游戏中所有系统都服务于这条循环。

### 2.1 子系统衍生关系

基于核心循环，向外衍生三个子系统：

```
                    ┌──────────────────────────┐
                    │      核心玩法循环        │
                    │  角色界面 → 事件 → 回馈  │
                    └──────────┬───────────────┘
                               │
          ┌────────────────────┼────────────────────┐
          ▼                    ▼                    ▼
  ┌───────────────┐   ┌───────────────┐   ┌───────────────┐
  │  事件响应能力  │   │   战斗系统    │   │   回馈收益系统  │
  │               │   │               │   │               │
  │ · 事件生成器  │   │ · 战斗事件    │   │ · 角色回馈    │
  │ · 场景约束    │   │ · 战斗结算    │   │ · 战斗回馈    │
  │ · 五行性格    │   │ · 战斗奖励    │   │ · 事件回馈    │
  └───────────────┘   └───────────────┘   └───────────────┘
```

### 2.2 三条回馈循环

游戏内有三条并行的成长回馈循环，均服务于角色成长：

**循环 A：角色成长循环（核心）**
```
修炼/吐纳/境界提升 → 角色属性成长 → 解锁更强事件和战斗 → 获得更好回馈 → 继续成长
```

**循环 B：战斗成长循环**
```
进入战斗事件 → 战斗选项选择 → 结算（胜负+奖励）→ 战利品/灵气/属性 → 角色变强 → 接受更强挑战
```

**循环 C：事件成长循环**
```
进入事件 → 选项决策（受五行性格影响）→ 结算 + 五行性格偏移 → 角色属性+性格双重成长 → 新的事件倾向形成
```

### 2.3 核心界面入口

游戏的主入口是**角色界面**。

玩家从角色界面出发，选择历练方向（吸纳/奇遇/战斗/危机），进入相应的事件循环，获得回馈后回到角色界面，查看成长结果。

```
角色界面
    │
    ├── 吸纳灵气 ──→ 事件循环 ──→ 回馈
    │
    ├── 奇遇探宝 ──→ 事件循环 ──→ 回馈
    │
    ├── 争斗切磋 ──→ 战斗循环 ──→ 回馈
    │
    └── 危机四伏 ──→ 危机循环 ──→ 回馈
```

## 三、核心处理点

核心处理点回答：事件结算后，回报如何落到可感知、可记录、可叠加的维度。本文档先定义第一个处理点，后续处理点按需补充。

### 3.1 事件回报（属性 / 剧情 / 装备）

事件结算的主要出口：把一次选择的结果，拆成属性、剧情、装备三类回报（可叠加）。

| 维度 | 回报内容 | 详设文档 |
|------|----------|----------|
| **属性方面** | 六维属性变化、境界相关成长、灵根经验 | 详见 `02-角色属性系统.md` |
| **剧情方面** | 五行性格偏移、关系维度变化、事件链解锁 | 详见 `10-角色性格属性系统.md`（性格维）+ `11-奇遇生成器框架.md`（事件链相关：`05-事件系统.md`） |
| **装备方面** | 掉落、品质、词缀、强化材料 | 详见 `03-装备系统.md` |

**约束：**

1. **单次至少一个维度回报**：每次事件结算至少产出属性 / 剧情 / 装备中的一类，禁止「空结算」。
2. **数值化记录**：回报必须可写入存档与日志（数值或枚举），避免纯叙事无状态变化。
3. **高风险高回报**：风险档位越高，期望回报越高（幅度、稀有度或链解锁权重）。
4. **三类可叠加，但至少一类主要**：允许同时给出多类回报；须指定一类为主要回报，便于事件设计与平衡。
