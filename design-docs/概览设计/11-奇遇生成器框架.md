## 一、核心定位

奇遇生成器是一个**事件模板生成系统**。给定场景类型 + 角色当前状态，生成完整的奇遇事件结构（描述、选项、奖励、性格偏移）。

不是写死模板，而是**可组合的流水线**。

---

## 二、生成器输入（Inputs）

```typescript
interface GeneratorContext {
  // 角色状态
  realm: Realm;                    // 当前境界
  stats: Stats;                    // 六维属性
  fiveElements: FiveElements;      // 五行性格值（10维）
  triggeredEvents: Set<string>;    // 已触发事件ID（用于去重）

  // 场景上下文
  locationType: LocationType;      // 当前位置类型
  recentEventTypes: EventType[];   // 最近3个事件类型（避免重复）

  // 生成参数
  targetEventType: EventType;      // 目标事件类型
  difficulty: 'easy' | 'medium' | 'hard';
}
```

### 位置类型（`LocationType`）

| 值 | 场景 |
|---|------|
| `wild` | 野外 |
| `cave` | 洞穴/洞府 |
| `secret_realm` | 秘境 |
| `sect` | 宗门 |
| `city` | 坊市/城镇 |
| `battlefield` | 战场 |
| `divine_land` | 神迹/灵地 |

### 事件类型（`EventType`）

继承现有：`奇遇` | `机缘` | `抉择` | `危机`

## 三、生成器输出（Outputs）

```typescript
interface GeneratedEvent {
  id: string;                      // 唯一标识，格式：gen_{type}_{timestamp}
  title: string;
  description: string;
  type: EventType;
  realmRange: [Realm, Realm];

  options: GeneratedOption[];

  // 元数据
  tags: string[];                  // 场景标签，用于过滤
  weight: number;                  // 出现权重
  oneTime: boolean;
}

interface GeneratedOption {
  text: string;                    // 选项描述
  resultText: string;              // 结果描述
  riskLevel: RiskLevel;            // 风险等级

  reward: EventReward;             // 奖励（灵气/属性/经验/金币/物品）
  temperamentShift: TemperamentShift[];  // 性格偏移
  relationChanges?: RelationChange[];    // 关系变化

  // 条件
  condition?: {
    realm?: Realm;
    statReq?: Partial<Stats>;
    temperamentReq?: Partial<FiveElements>;  // 性格门槛（可选）
  };
}
```

### 风险等级（`RiskLevel`）

| 等级 | 标签 | 含义 |
|------|------|------|
| 0 | 零 | 无任何风险，零收益或极低 |
| 1 | 低 | 低风险，低~中收益 |
| 2 | 中 | 中风险，中收益 |
| 3 | 高 | 高风险，高收益 |
| 4 | 极高 | 极高风险，可能有负面后果 |

## 四、五行性格偏移系统

> **本节已对齐 [10-角色性格属性系统.md](./10-角色性格属性系统.md) v1.0 锁定版。**

> **主战场速览**：性格（阳/阴）= 事件；灵魂 = 人际 + 战斗；肉体 = 战斗 / 身法体质。  
> 锚定词是设计总纲（校准尺），**不展示、不占数值**；其余三套量同源五行、各自演化。

### 4.1 五行性格结构（25 词三层）

按五行（**火 / 水 / 木 / 金 / 土**）组织**三套并行量 + 一层锚定词**：

| 五行 | 锚定（总纲） | 性格·阳（价值取向） | 性格·阴（价值取向） | 灵魂（响应方式） | 肉体（身法/体质） |
|------|------------|--------------------|--------------------|------------------|------------------|
| **火** | **激进** | 热血（积极介入） | 贪婪（掠夺资源） | 果断 | 迅捷 |
| **水** | **交融** | 包容（忠贞接纳） | 沉溺（失度渗入、难以抽身） | 变通 | 灵巧 |
| **木** | **繁茂** | 传承（延续珍视之物） | 侵夺（以扩展侵占他人根基） | 执着 | 生机 |
| **金** | **坚刚** | 守正（守正道、有所不为） | 冷酷（不择手段） | 刚毅 | 坚韧 |
| **土** | **固守** | 厚德（承载滋养） | 吝啬（过度守护不放） | 隐忍 | 厚重 |

> **锚定词**：五词；仅做设计校准——**设计总纲，不展示，不占数值**；是性格 / 灵魂 / 肉体选词的共同底色（详见 10-角色性格属性系统.md §二）。

**结构要点**：

- **性格·阳 / 性格·阴**（**主战场：事件**，价值取向）：同一行阳与阴并立（非顶替），各为非负程度值；玩家可见共 10 词。
- **灵魂**（**主战场：人际 + 战斗**，响应方式）：每行一个非负程度值；玩家可见 5 词。
- **肉体**（**主战场：战斗 / 身法体质**）：每行一个非负程度值；玩家可见 5 词。
- **三套量化各自独立演化**，即使同一行里出现近义词（如金·灵魂「刚毅」与金·肉体「坚韧」），也不视为同一属性。

### 4.2 与修为灵根（WuXing）的关系

**修为灵根 ≠ 五行性格，两者不在同一层。**

| 系统 | 角色 | 层 |
|------|------|----|
| **修为灵根（WuXing）** | 修炼资质，`character.element`（单值 `fire | water | wood | metal | earth`） | 角色天生属性 |
| **锚定词** | 设计总纲（校准尺） | 设计层（**不展示、不占数值**） |
| **五行性格（25 词）** | 性格阳/阴 + 灵魂 + 肉体 三套并行量 | 角色可演化属性 |

- 修为灵根是**角色天生资质**，作为五行性格的**初始参考**（开局的初貌）。
- 性格成形后**独立演化**，**不再受修为灵根约束**。
- **锚定词 ≠ 灵根**：锚定词是设计总纲（校准尺），灵根是角色资质（属性）。两者不同层，不应混淆。
- 性格·阳 / 性格·阴 / 灵魂 / 肉体三套量**各自演化**，互不绑定（详见 10-角色性格属性系统.md §十）。

### 4.3 五行性格初始化

**初始化逻辑在角色系统执行，框架只描述输入接口，不定义算法。**

角色系统负责根据角色的修为灵根（`character.element`）生成五行性格的**初始画像**，并写入 `Character` 对象。生成器只读取该字段，不负责计算。

框架要求的 `GeneratorContext.fiveElements` 字段（见第二章）必须包含以下**三层结构**：

- **性格·阳**：`personality.{五行}.yang`（火/水/木/金/土，共 5 个非负程度值）
- **性格·阴**：`personality.{五行}.yin`（同上，共 5 个非负程度值）
- **灵魂**：`soul.{五行}`（火/水/木/金/土，共 5 个非负程度值）
- **肉体**：`body.{五行}`（火/水/木/金/土，共 5 个非负程度值）

> **锚定词不出现在该接口中**——它是设计层，不进入量化接口。

### 4.4 后续修正机制

五行性格三层量**各自演化**，由对应主战场驱动：

| 量 | 驱动场景 | 偏移来源 |
|------|---------|---------|
| **性格·阳 / 性格·阴** | **事件选项结算**（主战场=事件） | 选项声明的 `temperamentShift`（行 · 阳 / 行 · 阴） |
| **灵魂** | **人际 + 战斗结算**（主战场=人际+战斗） | 对应体验驱动的偏移 |
| **肉体** | **战斗 / 身法体质结算**（主战场=战斗-身法体质） | 对应体验驱动的偏移 |

**通用规则**：

1. **修为灵根不再影响**这三套数值；成形后完全独立演化。
2. 数值**下限为 0**。
3. **上限**是否封顶、是否设软上限、是否衰减 / 对冲 / 仅用占比解读，留作**开放设计点**（与 10-角色性格属性系统.md §十一、§十二 对齐）。
4. 偏移量为有符号增量（常见 ±1 量级）。
5. **锚定词不在数值层**，不写入偏移接口。

### 4.5 性格偏移接口（由事件模板定义）

性格偏移由事件模板自行定义，框架只提供接口规范。

#### 接口格式

每个选项的 `temperamentShift` 字段格式如下：

| 字段 | 类型 | 说明 |
|------|------|------|
| `dimension` | `DimensionKey` | 三层 + 五行，如 `personality.fire.yang`、`soul.fire`、`body.fire` |
| `value` | `number` | 偏移量，范围 ±1（正为程度增加，负为减少）|

**命名约定（建议）**：

- **性格层**（10 个，价值取向 · 事件主战场）：`personality.{五行}.yang` / `personality.{五行}.yin`
- **灵魂层**（5 个，响应方式 · 人际 + 战斗主战场）：`soul.{五行}`
- **肉体层**（5 个，身法 / 体质 · 战斗主战场）：`body.{五行}`
- **锚定词不写入偏移字段**。

## 五、场景组件库（可组合）

生成器使用组件库组合生成事件描述和选项。

### 5.1 场景的本质：约束而非内容

**场景是事件的约束层，不是独立的内容单元。**

场景本身没有独立意义，它的作用是为事件提供逻辑约束，让事件在物理背景、时机、参与者上显得自洽。约束越自洽，事件越真实。

**三类约束：**

| 约束维度 | 内容 | 举例 |
|---------|------|------|
| 位置约束 | 事件必须发生在某类场景 | 必须在宗门内、必须在洞府 |
| 时间约束 | 事件必须发生在特定时机 | 突破时、历练中、深夜 |
| 参与者约束 | 事件必须有特定的在场者 | 师兄在场、外来修士路过 |

**约束的自洽原则：**

- 约束之间不得冲突。冲突的约束会让事件荒谬，损害真实感。
- 示例：❌「在洞府内遇到街头卖艺的凡人」→ 地点和参与者矛盾
- 示例：❌「在战场废墟里单独存在完好无损的法器」→ 背景和物品状态矛盾
- 示例：✅「在宗门内师兄赠予修炼心得」→ 地点和人物关系自洽

**场景模板在生成器中的角色：**

场景模板定义一组自洽的约束组合（位置类型 + 关键词 + 描述模板），生成器根据当前 context 匹配最合适的模板，再组装事件选项。场景约束不决定事件结果，只决定事件是否在逻辑上成立。

### 5.3 奖励组件

```typescript
interface RewardComponent {
  spiritTypes: (keyof SpiritReward)[];  // 灵气类型组合
  baseRange: [number, number];           // 基础范围 [min, max]
  scalingByRealm: Record<Realm, [number, number]>;  // 随境界缩放
}

// 示例
const REWARD_COMPONENTS: Record<RiskLevel, RewardComponent> = {
  0: { spiritTypes: ['wood'], baseRange: [3, 8], scalingByRealm: {...} },
```
