## 一、定位

本章锁定登仙战斗系统的**基础设计哲学**，回答一个最底层的问题：

> 「战斗系统应该围绕什么来设计？」

旧实现 `04-技能与战斗系统.md` 是「回合制 1v1 + 技能普攻」模型，已与新设计哲学脱节。本框架定义**多对多 + 卡牌构筑式**的新战斗方向，全部设计从「三原则」出发。

**三原则是基础哲学（最底层的「为什么」），不是具体规则。** 具体规则（牌组容量数值、卡牌类型划分、抽卡机制、行动顺序等）由三原则派生，待后续单独文档展开。

## 二、设计哲学：三原则

游戏内战斗系统的全部设计都从这三原则出发。三原则之间**互不重叠**，合起来覆盖「属性 ↔ 牌组 ↔ 卡牌」的完整关系。

| 原则 | 内容 | 动词 |
|---|---|---|
| 原则 1 | 属性 → 容量 + 类型限制 | 约束 |
| 原则 2 | 术法系统 → 卡牌来源 | 产出 |
| 原则 3 | 卡牌 ↔ 属性耦合 | 一切 ↔ 关系 |

### 2.1 原则 1：属性 → 容量 + 类型限制（结构约束）

角色属性决定两个东西：

- **牌组容量（量）**：能装多少张卡
- **卡牌类型限制（结构）**：能装什么类型的卡

不是「门开多大」，而是「门后有什么房间」。属性让角色的牌组从**数量差异**升级到**类型差异**，角色差异化从这里来。

**当前锁定**：
- 来源属性：**灵魂 + 肉体**（取自 `10-角色性格属性系统.md` v1.0，战斗绑定）
- 「其他属性」（修为 / 灵根 / 性格）**不参与**牌组结构约束
- 类型限制的具体规则（按 25 词映射 / 按功能分 / 混合）→ 见 §七 待拍板

### 2.2 原则 2：术法系统 → 卡牌来源（产出 / 解锁）

玩家**不能自由选卡**。卡牌内容由「术法系统」决定：

- **来源**：术法系统产出 / 解锁卡 → 进入手集（可选池）
- **强度挂钩**：卡牌效果强度 → 必须挂钩某些角色属性（否则成长 → 战斗无正反馈）

**术语区分**：
- 「手集」= 可选池（玩家从中选牌装入牌组）
- 「卡牌内容」= 卡本身（其效果与设计）
- 原则 2 管的是**卡牌内容**的产出与设计；原则 1 管的是**怎么装进牌组**

**当前锁定**：
- 强度挂钩可以挂「某些属性」，**不一定是灵魂 / 肉体**，也可能是新设计的属性轴
- 候选属性：修为（境界）/ 灵力 / 悟性 / 神识 / 道行 / 真元 → 见 §七 待拍板

### 2.3 原则 3：卡牌 ↔ 属性耦合（一切 ↔ 关系）

将原原则 2 的「强度挂钩」与原原则 3 的「耦合」**合并**：卡 ↔ 属性之间的一切关系都归到这里。

包含 4 类子关系：

| 子关系 | 含义 | 主导属性（当前锁定） |
|---|---|---|
| **强度挂钩** | 卡数值 → 属性 | 修为 / 境界（待定，见 §七） |
| **类型耦合** | 哪些卡对哪些属性敏感 / 修正 | 灵魂 + 肉体 |
| **战斗响应** | 卡牌出手 / 反应时机 / 模式 | 灵魂 |
| **体质修正** | 卡牌物理强度 / 身法 / 体魄 | 肉体 |

**当前锁定**：
- 灵魂 → 战斗响应（卡的「怎么打」）
- 肉体 → 体质修正（卡的「打多重」）
- 类型耦合 + 强度挂钩的具体属性 → 待拍板

## 三、三原则的协同

三原则回答的是三个不同层级的问题，互不重叠：

| 原则 | 回答的问题 |
|---|---|
| 原则 1 | 属性**怎么约束**牌组结构 |
| 原则 2 | 卡牌**从哪里来** |
| 原则 3 | 属性**怎么影响**每张卡 |

合起来覆盖：**属性 → 牌组结构 / 卡牌来源 / 单卡效果** 三个层级。任何具体设计都应能映射回其中一个或多个原则。

---

## 四、4 维度映射（战术支柱）

三原则是「基础哲学」（最底层），落地到战斗还需要「战术支柱」——4 个维度：

| 维度 | 在战斗中的角色 | 类比 ESTIAH |
|---|---|---|
| **自身能力** | 静态层：六维 + 被动 + 天赋 | 决定 Spirit / HP / 防御 |
| **法术** | 主动层：技能卡（主动技） | Charm 的 Offensive |
| **法器** | 装备层：激发附属卡 / 被动触发器 | 装备限制 charm 使用 + 附加效果 |
| **阵法** | 空间层：站位 + 阵眼 + 范围效果 | ESTIAH 没有，多对多独家 |

**4 维度 vs 三原则的关系**：

- 三原则 = **基础哲学**（最底层，回答「为什么」）
- 4 维度 = **战术支柱**（中间层，回答「战斗包含哪些子系统」）
- 不冲突；4 维度是三原则的**承载结构**

## 五、多对多框架要点（应用场景）

三原则在「多对多 + 卡牌构筑」场景下的关键应用（待逐项展开，此处仅锚定要点）：

1. **目标选择**：从随机单体 → 智能目标 + 玩家强制 + 阵法阵眼
2. **行动顺序**：从顺序制 → 行动条 / 灵力槽制（速度决定填充率，高速可同回合多次行动）
3. **多牌组并存**：每个单位同时持有「法术牌组 + 法器牌组 + 阵法牌组」三层
4. **空间层**：1v1 没有站位 → 多对多必须引入站位（前排 / 后排 / 阵法格）
5. **阵法独立维度**：ESTIAH 无，多对多独有

## 六、与已有系统的接入点

| 已有系统 | 三原则里的角色 | 锁定来源 |
|---|---|---|
| **灵魂** | 原则 1（容量 + 类型）+ 原则 3（战斗响应） | `10-角色性格属性系统.md` v1.0 |
| **肉体** | 原则 1（容量 + 类型）+ 原则 3（体质修正） | `10-角色性格属性系统.md` v1.0 |
| **五行灵根** | 原则 2（限定可学术法） | `02-角色属性系统.md` |
| **修为境界** | 原则 1（解锁 + 容量）+ 原则 2（解锁新卡） | `02-角色属性系统.md` |
| **性格阴阳** | **不上战斗**（不变） | `10-角色性格属性系统.md` v1.0 |

**关键锁定**：

- **灵魂 + 肉体 独占战斗绑定**（性格阴阳 / 灵根 均不参与战斗）
- **灵根 → 完全脱离战斗**，只走成长系统（修炼进度 / 顿悟 / 突破 / 解锁手集）
- **性格阴阳 → 完全不上战斗**，只走事件系统
