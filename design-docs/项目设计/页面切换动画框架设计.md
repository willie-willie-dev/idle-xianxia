## 1. 现有页面结构分析

### 页面清单

| Screen Key | 组件 | 路由方式 | 是否有动画 |
|---|---|---|---|
| `entry` | `EntryScreen` | `navigateTo('entry')` | ❌ 无 |
| `create` | `CharacterCreate` | `navigateTo('create')` | ❌ 无 |
| `game` | `GameScreen` | `navigateTo('game')` | ❌ 无（内部手风琴展开有） |
| `event` | `EventScreen` | `navigateToEvent()` | ✅ `framer-motion` 淡入 + 位移（仅入场，无离场） |

**当前路由逻辑：**

```tsx
// App.tsx — 直接条件渲染，无任何过渡
if (screen === 'entry') return <EntryScreen />;
if (screen === 'create') return <CharacterCreate />;
if (screen === 'event') return <EventScreen ... />;
return <GameScreen />;
```

`navigateTo()` 来自 `useAccountStore`，直接修改 `screen` 状态，无过渡层。

**EventScreen 现有入场动画：**
```tsx
<motion.div
  initial={{ opacity: 0, y: 20 }}
  animate={{ opacity: 1, y: 0 }}
  transition={{ duration: 0.4, ease: 'easeOut' }}
>
```
仅作用于 EventScreen 自身，未覆盖其他页面切换。

## 2. 动画框架设计方案

### 2.1 设计目标

1. **标准化虚化效果** — 所有页面跳转统一 blur → fade → 切换 → fade in + blur out
2. **修仙主题动画** — 云朵飘动、灵气缭绕、化虚感
3. **全局框架** — 一次实现，全局生效，无需每个页面单独编写
4. **不侵入现有代码** — 通过 Context + overlay 方式接入，对现有 Screen 组件零修改

---

### 2.2 架构总览

```
App
 └── PageTransitionProvider [Context]
      ├── PageTransitionOverlay [fixed, z-index: 9999]
      │    ├── CloudLayer          ← 云朵飘动（横向漂移）
      │    └── SpiritMistEffect    ← 灵气雾效（缭绕扩散）
      └── Children (App content)
```

**过渡流程：**

```
触发 navigateTo('xxx')
  → startTransition(targetScreen)
  → isTransitioning = true（Overlay 显现）
  → 等待 400ms（动画淡入）
  → 真正执行 screen 切换
  → 等待 300ms（停留展示）
  → isTransitioning = false（Overlay 退场）
```

---

### 2.3 组件规格

#### `PageTransitionContext` & `usePageTransition()`

**Context 值：**
```typescript
interface PageTransitionContextValue {
  isTransitioning: boolean;      // 是否正在过渡中
  transitioningTo: Screen | null; // 即将跳转的目标页面
  startTransition: (target: Screen) => Promise<void>; // 触发过渡
}
```

**Hook 用法（Screen 内部，无需关心）：**
```typescript
// Screen 组件中，onClick 时：
const { startTransition } = usePageTransition();
onClick={() => startTransition('game')}
// 之后 navigateTo 会被自动拦截，等待过渡完成后再执行
```

**实现原理：**  
`startTransition` 拦截实际导航，内部先触发 overlay 显示，等动画完成后 callback 通知调用者真正执行 navigateTo。

#### `PageTransitionOverlay`

| 属性 | 说明 |
|---|---|
| 类型 | 固定定位全屏遮罩 |
| z-index | 9999 |
| 默认 | `opacity: 0; pointer-events: none` |
| 过渡中 | `opacity: 1; pointer-events: all` |
| 背景 | 径向渐变模拟仙气氛围，`.7 - .9` 透明度黑色底 |

#### `CloudLayer`

| 属性 | 说明 |
|---|---|
| 动画元素 | 5-8 个 `<div>` 云朵，随机分布在屏幕上方 |
| 动画方式 | CSS `@keyframes` 横向飘动（`translateX`） |
| 大小 | 60px - 120px 直径（随机） |
| 透明度 | 0.12 - 0.25 |
| 颜色 | 白色 / 淡金色（`rgba(255,255,255,0.15)`） |
| 飘动方向 | 从左到右，或从右到左（随机） |
| 飘动时长 | 8s - 16s（每个云朵不同） |
| 停留位置 | 屏幕上方 `top: -10% ~ -25%` |

**云朵形状：**  
使用 CSS `border-radius: 50% 60% 40% 70% / 60% 30% 70% 40%` 不规则圆形，模拟棉花云效果。

#### `SpiritMistEffect`

| 属性 | 说明 |
|---|---|
| 动画元素 | 全屏 `<div>` 覆盖渐变透明层 |
| 动画方式 | `@keyframes` 水平漂移 + 透明度呼吸 |
| 颜色 | 青色（`rgba(79,195,247,0.08)`）+ 淡金色（`rgba(212,168,67,0.05)`） |
| 效果 | 底部向上缭绕感，mask 渐变隐藏 |

#### CSS 过渡规格

```css
/* Overlay 入场 */
.page-transition-overlay {
  opacity: 0;
  pointer-events: none;
  transition: opacity 0.4s ease;
}
.page-transition-overlay.active {
  opacity: 1;
  pointer-events: all;
}

/* 云朵飘动 */
@keyframes cloud-drift-right {
  0%   { transform: translateX(-120px) translateY(0); }
  100% { transform: translateX(calc(100vw + 120px)) translateY(-20px); }
}
@keyframes cloud-drift-left {
  0%   { transform: translateX(120px) translateY(0); }
  100% { transform: translateX(calc(-100vw - 120px)) translateY(20px); }
}

/* 灵气缭绕 */
@keyframes spirit-mist-drift {
  0%, 100% {
    opacity: 0.4;
    transform: translateX(-3%) scaleY(1);
  }
  50% {
    opacity: 0.7;
    transform: translateX(3%) scaleY(1.05);
  }
}

/* 灵气粒子（可选加强） */
@keyframes spirit-particle-rise {
  0%   { transform: translateY(0) scale(1); opacity: 0.6; }
  100% { transform: translateY(-60px) scale(0.4); opacity: 0; }
}
```

### 2.6 技术选型

- **动画方式：** 纯 CSS `@keyframes` + React state（无额外 animation library）
- **原因：** 项目已使用 framer-motion，但 framer-motion 更适合 Component-level 动画；overlay 这种全局层用 CSS 更轻量、且更易控制 `pointer-events`
- **Context 管理：** React Context（轻量，无须引入 zustand 等状态管理库）
- **过渡状态机：** Promise-based async/await，避免回调地狱
