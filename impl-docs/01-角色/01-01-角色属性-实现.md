# 角色属性（实现）

对照：`design-docs/01-角色/01-01-角色属性系统.md`、`01-08-角色属性总览.md`

## 实际落地的字段

| 分类 | 字段 | 说明 |
|---|---|---|
| 身份 | 名字、id、创建/更新时间 | 名字非空；删除角色时清 activeId |
| 灵根 | 乾 / 坤 / 金 / 木 / 水 / 火 / 土 | 7 项，合计必须 100（±0.01），缺键或非数字直接拒绝建号 |
| 主属性 | 五行之一 | 由灵根最大值推导，平手按 金→木→水→火→土 取前者；**目前只用于展示** |
| 修炼 | 境界 + 阶位、修为、本境上限、突破阈值 | 见 `01-05` |
| 功法 | 3 个槽位（可为空）+ 当前生效槽 | 槽里只存功法引用，不存数值 |
| 背包 | 物品列表 | 目前只有功法一类；同一功法只留一本 |
| 进度 | 已完成事件 id、历练次数、剧情标记、天数、随机种子 | 种子与已完成事件都进存档 |
| 元数据 | 存档版本号 | 字段增删时做兜底迁移 |

## 规则

- 建号时灵根合计 = 100（±0.01），否则**不落库**
- 一套 rig 校验：7 个键必须都在且为有限非负数；缺键会报错（而不是被 NaN 比较绕过）
- 老存档读取时统一补齐新增字段，并按「境界 + 阶位」重算阈值与上限
- 删除角色会清掉当前激活角色

## 没做的

- 六维属性、寿元/年龄、容貌、性格、精神状态、装备栏
- 多存档槽（只有「多个角色 + 一个 activeId」）
- 属性对数值的实际影响（主属性目前纯展示）

## 与设计的差异

- 设计 01-01 的字段远多于实现（性格 5 维、战意、精神、装备），实现只取「能跑循环」的最小集
- 设计有灵根容纳量 / 灵根池概念，实现没有
- 详见 `../差异对照表.md` 行 A1–A4
