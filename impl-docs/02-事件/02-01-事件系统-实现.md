# 事件系统（实现）

对照：`design-docs/02-事件/02-01-事件系统.md`

## 结构

- 事件池 **24 条**，按「境界 + 阶位」分池（9 个池）
- 每阶至少 2 条，分布：炼气 3/3/2、筑基 2/4/2、金丹 3/3/2
- 每条事件：标题、正文、2–3 个选项
- 每个选项包含：选项文字、**结果交代**、修为增益、可选的剧情标记与功法掉落

## 抽取规则

| 规则 | 实现 |
|---|---|
| 抽池 | 只抽「当前境界 + 当前阶位」的池 |
| 不重复 | 抽过的事件进「已完成」，不再出现 |
| 抽空 | 该阶位全部抽完返回「无事件」，种子仍推进 |
| 随机 | 线性同余种子，种子进存档，可复现 |
| 消耗 | **0**（历练不消耗任何资源、不需要功法） |
| 耗时 | 事件可带 `days`（2–7 天，5 条事件有），其余 0 天 |

## 选项结算（三类奖励）

| 奖励 | 说明 |
|---|---|
| 修为 | 每个选项都有（+5~15；没写时兜底 +5） |
| 剧情标记 | 可累積的短标签（如「结善缘」「藏锋」），去重后进存档 |
| 功法掉落 | 选项级 `grants`，进背包；同一功法只保留一本，重复获得只提示「已拥有」 |

## 结果交代（今天新增）

- 每个选项都写了 `outcome`：2–3 句、第二人称、承接该选项动作写出具体后果
- 同一事件内不同选项的交代**两两不同**
- 选完后 UI 展示：`你的选择：<选项原文>` + 结果交代 + 徽标（修为 / 获得功法 / 剧情标记）+「继续」

## 掉落表（5 本功法）

| 事件 | 条件 | 功法 |
|---|---|---|
| 山道拾遗（炼气·前期） | **三个选项都掉** | 青木诀（新手保底） |
| 洞府灵脉（筑基） | 选项 0 | 烈火诀 |
| 渡口论道三日（筑基） | 选项 0 | 厚土诀 |
| 金丹初转（金丹） | 选项 0 | 庚金诀 |
| 心境失守（金丹） | 选项 0 | 玄水诀 |

## 与设计的差异

- 设计有事件**权重**、按天**刷新**、**消耗**资源；实现是等概率、不重复、零消耗
- 设计的事件有 `timeCost`（如 7 天），实现用 `days`（2–7 天，仅部分事件）
- 设计的奖励结算更复杂（可能含物品/装备），实现只有修为 + 剧情标记 + 功法
- 详见 `../差异对照表.md` 行 D1–D4
