# 时间系统（实现）

对照：`design-docs/02-事件/02-03-时间系统.md`

## 单位与推进

- **最小单位：天**（不设时辰/昼夜）
- 时间由「动作」推进，次数写进存档（天数 + 累计推进次数）
- 逐天推进：一次推 N 天，会对每一天各触发一遍「日初 / 日终」钩子

## 各动作耗时

| 动作 | 天数 |
|---|---|
| 吸收灵气 | 1 |
| 突破 | 0（不耗天，但会走钩子管线） |
| 历练 | 事件自带 `days`（2–7 天）；没写则 0 |

## 钩子（骨架，暂未启用具体逻辑）

预留 5 类时机：日初、日终、动作前、动作后、境界变化。

每个钩子声明：
- 唯一 id 与显示名
- 触发时机
- 优先级（小者先跑，同优先级按注册顺序）
- 可选的原因过滤（只在这些动作下跑）
- 返回「时间补丁」或「角色补丁」，由时间系统统一合并

规则：
- 钩子**不能直接改时间**，只能返回补丁；只允许改累计次数，不允许改天数
- 单个钩子抛错**不中断**推进，错误吞掉并继续
- 时间为 0 天时只触发「动作前 / 动作后」

## 与设计的差异

- 设计的时间系统与事件、寿元、季节相关；实现只做「天 + 耗时」
- 设计的钩子体系更密（事件刷新、寿元衰减、天气等）；实现只留骨架，未接具体逻辑
- 详见 `../差异对照表.md` 行 E1–E3
